# T4q Existing Platen Boundary Capability Audit

## Purpose

T4p concluded that the reduced triaxial route needs explicit platen boundary
conditions rather than the diagnostic `CapConfiningStress` acceleration patch.
This audit checks whether the current GeoDualSPHysics XML/source capabilities
can support a first XML-only platen workflow.

## Existing Fixed And Moving Boundary Support

The base DualSPHysics XML workflow already supports:

- fixed `mkbound` groups generated by `setmkbound`;
- moving `mkbound` groups linked to `<motion><objreal ref="...">`;
- prescribed translational velocity using `mvrect`;
- standard SPH interaction between normal fluid/material particles and
  fixed/moving boundary particles.

Reference examples include:

- `examples/motion/Motion01.xml`, where one `mkbound` block is fixed and one
  is moving;
- `examples/main/03_MovingSquare/CaseMovingSquare_Def.xml`, where a moving
  square is driven by `mvrect`;
- wave-maker examples, where moving boundaries are postprocessed with
  `BoundaryVTK`.

Therefore a first platen route can be built without source changes by using
top and bottom `mkbound` groups.

## Platen Group Capability

The current generator can create separate platen particle blocks:

- bottom platen: `mkbound=2`, fixed by omitting motion;
- top platen: `mkbound=1`, prescribed by an `<objreal ref="1">` motion block;
- specimen: `mkfluid=0`, still the only u-pw soil material.

This is cleaner than the previous reduced smoke cases, where the top loading
layer was `mkfluid=1` and was accelerated by `AccInput`.

## Contact And Force Transfer

An XML-only platen route can test whether standard boundary-fluid/material
interactions transfer axial motion into the specimen. It does not yet prove a
strict triaxial loading formulation because:

- the platen is a DualSPHysics boundary object, not a soil material;
- the contact law is the existing SPH boundary treatment;
- reaction force output is not automatically a validated triaxial axial force;
- no special u-pw platen contact law is implemented.

This is acceptable for T4q because the goal is feasibility, grouping, and smoke
stability.

## Avoiding Soil Constitutive And PR Updates On Platens

Using `mkbound` platens avoids the main contamination seen in the AccInput
route:

- platen particles are not `mkfluid` soil material;
- they are not part of the soil constitutive update;
- they are not included in u-pw pore-pressure PR material updates;
- they can be excluded from measurement and p-q statistics by type/mk.

This is the main reason to prefer `mkbound` platens over material top/bottom
cap layers for strict triaxial development.

## Reaction / Axial Stress Output

The current XML-only route can estimate a reaction proxy only indirectly from:

- platen motion and specimen deformation;
- boundary-particle velocity stability;
- optional `ComputeForces` / force postprocessing if a reliable mkbound force
  extraction route is configured later.

T4q therefore treats reaction as a proxy, not a validated axial stress. A
future source enhancement may be needed for robust top/bottom reaction
accumulation.

## AccInput Difference

`AccInput` applies a body acceleration to selected `mkfluid` particles. It is
useful for early smoke tests but does not impose a rigid platen displacement or
velocity, does not supply a fixed bottom platen, and does not provide a clean
reaction force. It should remain a smoke route only.

## XML-Only Feasibility Decision

T4q can proceed with an XML-only feasibility prototype:

1. generate a soil cylinder as `mkfluid=0`;
2. generate bottom and top cylindrical platen blocks as separate `mkbound`
   groups;
3. keep the bottom platen fixed;
4. prescribe top platen downward velocity using `<motion>`;
5. run with `PorePressureFeedback=0` first;
6. optionally add lateral `FlexibleConfiningStress` to the specimen.

No source patch is required for the first T4q smoke gate. A source patch is
only needed later if reaction output or stricter platen constraints are
required.
