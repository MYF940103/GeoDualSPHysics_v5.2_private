# TINT1 Pore-Pressure Update Callchain Audit

Date: 2026-05-14

## Objective

This audit maps where the PR pore-pressure rate is computed, where
`PorePress` is advanced, and which time-stage variables are used by the
feedback acceleration in the current CPU and GPU Verlet/Symplectic schemes.

TINT1 is a staging audit only. It does not change the PR governing equation,
does not change boundary operators, and does not run new simulations.

## Update Definitions

The CPU pore-pressure update is implemented in
`source/JSphCpu.cpp:2228`:

```cpp
porepress[p1] += double(porepressrate[p1]) * dt;
```

The GPU equivalent is implemented in `source/JSphGpu.cpp:1046`, which launches
the kernel wrapper in `source/JSphGpu_ker.cu:3950`.

The PR rate on CPU is assembled in `source/JSphCpu.cpp:2195` as:

```cpp
porepressrate = (Kw / n) * (-DivVel + k/(rho_w g) LapPorePress + k LapZ)
```

with `LapZ` active only when `HydraulicElevationSource` is enabled.

On GPU, `JSphGpu::ComputeHydroPrDiagnosticsGpu()` at
`source/JSphGpu.cpp:880` computes `DivVel`, `LapPorePress`, `LapZ`, and
`PorePressRate` in a single diagnostic kernel.

## CPU Call Order

### Interaction Stage

`JSphCpuSingle::Interaction_Forces()` starts at
`source/JSphCpuSingle.cpp:949`. After the normal SPH force interaction, the
u-pw sequence is:

1. `ComputeHydroDivVel()` at `source/JSphCpuSingle.cpp:971`.
2. `ComputeHydroLapPorePress()` at `source/JSphCpuSingle.cpp:972`.
3. `ComputeHydroLapZ()` at `source/JSphCpuSingle.cpp:973`.
4. `ApplyPorePressureBoundaryOperator()` at `source/JSphCpuSingle.cpp:978`
   for operators `1`, `2`, or `3`.
5. Pore-pressure feedback acceleration candidates at
   `source/JSphCpuSingle.cpp:987-992`.
6. `ApplyPorePressureFeedback()` at `source/JSphCpuSingle.cpp:998-1000`.
7. `ComputeHydroPorePressRatePR()` at `source/JSphCpuSingle.cpp:1011`.

Therefore feedback acceleration is computed and applied before the scalar
pressure update. It uses the `PorePress` array that existed at the beginning of
that interaction stage.

### Verlet Step

`JSphCpuSingle::ComputeStep_Ver()` starts at `source/JSphCpuSingle.cpp:1153`.
The order is:

1. `Interaction_Forces(INTERSTEP_Verlet)`.
2. `DtVariable(true)`.
3. `UpdatePorePressure(..., dt, PorePressc, PorePressRatec)` at
   `source/JSphCpuSingle.cpp:1157`.
4. Optional Shepard correction.
5. Motion, shifting.
6. `ComputeVerlet(dt)` at `source/JSphCpuSingle.cpp:1168`.
7. Top drained clamp, bottom no-flux clamp, optional curved clamp.

Thus in Verlet the pressure rate is computed from pre-update mechanical state
and old pressure, then pressure is advanced before velocity, density, position,
and stress are advanced by `ComputeVerlet()`.

### Symplectic Step

`JSphCpuSingle::ComputeStep_Sym()` starts at `source/JSphCpuSingle.cpp:1195`.
The order is:

1. Predictor `Interaction_Forces(INTERSTEP_SymPredictor)`.
2. `ComputeSymplecticPre(dt)`.
3. Cell redivision.
4. Corrector `Interaction_Forces(INTERSTEP_SymCorrector)`.
5. `UpdatePorePressure(..., dt, PorePressc, PorePressRatec)` at
   `source/JSphCpuSingle.cpp:1214`.
6. Optional Shepard correction.
7. Shifting.
8. `ComputeSymplecticCorr(dt)` at `source/JSphCpuSingle.cpp:1223`.
9. Top drained clamp, bottom no-flux clamp, optional curved clamp.

In Symplectic, `PorePressRate` is computed from the predicted mechanical state
generated by `ComputeSymplecticPre()`, but the pressure array used by
`LapPorePress` and feedback is still the old pressure because there is no
pressure predictor.

## GPU Call Order

The GPU path mirrors the same broad placement:

- Verlet: `JSphGpuSingle::ComputeStep_Ver()` at
  `source/JSphGpuSingle.cpp:635` calls `Interaction_Forces()`, then
  `UpdatePorePressureGpu(dt)` at `source/JSphGpuSingle.cpp:638`, then
  `ComputeVerlet(dt)`.
- Symplectic: `JSphGpuSingle::ComputeStep_Sym()` at
  `source/JSphGpuSingle.cpp:676` calls predictor interaction,
  `ComputeSymplecticPre()`, corrector interaction, `UpdatePorePressureGpu(dt)`
  at `source/JSphGpuSingle.cpp:694`, then `ComputeSymplecticCorr()`.

GPU feedback is currently limited to `PorePressureFeedbackOperator=1`, and GPU
boundary operator support remains more limited than CPU. The pore-pressure
time-stage placement is nevertheless the same split: interaction computes rate
and feedback, then pressure is updated before the mechanical update/corrector.

## Variable Dependencies and Time Stage

| Quantity | CPU function | Depends on | Time stage in Verlet | Time stage in Symplectic |
|---|---|---|---|---|
| `DivVel` | `ComputeHydroDivVel()` | `Posc`, `Velrhopc`, `Codec` | pre-Verlet state | predicted/corrector state |
| `LapPorePress` | `ComputeHydroLapPorePress()` | `Posc`, `Velrhopc`, `PorePressc` | old pressure on pre-Verlet state | old pressure on predicted mechanical state |
| `LapZ` | `ComputeHydroLapZ()` | `Posc`, `Velrhopc`, hydraulic elevation | pre-Verlet state | predicted/corrector state |
| boundary contribution | `ApplyPorePressureBoundaryOperator()` | same plus boundary state | pre-Verlet state | predicted/corrector state |
| feedback acceleration | `ComputePorePressureAccel*()` | `Posc`, `Velrhopc`, `PorePressc` | old pressure | old pressure |
| applied acceleration | `ApplyPorePressureFeedback()` | feedback acceleration, `Acec` | added before `ComputeVerlet()` | added before `ComputeSymplecticCorr()` |
| scalar update | `UpdatePorePressure()` | `PorePressRatec`, `dt` | before `ComputeVerlet()` | before `ComputeSymplecticCorr()` |

## Boundary Correction Placement

For CPU, the optional Shepard regularization is applied after
`UpdatePorePressure()` and before the mechanical step. The top drained,
bottom no-flux, and curved-drained clamps are applied after the mechanical
step/corrector using `tpost=TimeStep+dt`.

For GPU, the post-update top/bottom clamps are applied immediately after
`UpdatePorePressureGpu()` and before the mechanical step/corrector. This is a
CPU/GPU placement difference for the simple post-update clamp stage, although
the rate/update/feedback placement is otherwise aligned.

## Conclusions

1. `PorePressRate` is computed inside `Interaction_Forces()`.
2. `PorePress` is advanced explicitly once per step, before the final
   mechanical update in both Verlet and Symplectic.
3. Feedback acceleration uses the pressure available during interaction, not
   the pressure just produced by `UpdatePorePressure()`.
4. Symplectic has no pore-pressure predictor. Its corrector rate uses
   predicted mechanical variables with old pressure.
5. CPU and GPU share the same broad time-stage split, but CPU and GPU differ
   in the exact timing of post-update top/bottom clamp relative to the
   mechanical step.
6. The current implementation is best described as a first-order explicit
   operator split for pore pressure, inserted into second-order mechanical
   stepping.
