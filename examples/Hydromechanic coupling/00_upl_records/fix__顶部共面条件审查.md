# 排水后顶部共面：离散必要条件与适用范围

状态：这是针对**未来可能超限**的预防性只读审查。记录时当前新 PR 尚未发生顶部共面错误；完整计算继续运行，建议未实施，边界放宽未验收。

## 结论

**排水开启后，顶部共面不是当前零孔压 Dirichlet 条件或 `TopVertical` 投影面积竖向载荷的数学必要条件。** 它目前仍是 `GetUplTopPlane(false)` 附带实施的近一维几何限制。封闭阶段则不同：真实顶部通量镜像依赖同一个水平面，共面及完整近顶行仍是现有离散的必要假设。

这支持“按实际使用平面的阶段区分验证职责”的方案，但不支持只看到 OFF 不共面就提高容差或取消所有顶部约束。当前完整 PR 计算及生产代码均未因本审查改动；以下只读结论尚不是放宽后实现的验收。

## 全部调用位置与实际用途

- [初始化调用](../../../src/source/JSphCpuUpl.cpp:674)：载荷模式为 PR TopVertical 时初始化不可变 top-owner，调用 `GetUplTopPlane(z,a,false)` 验证初始列几何。当前初始截面仍应平整、均匀覆盖一整个 X 周期。
- [水力调用](../../../src/source/JSphCpuUpl.cpp:276)：`topclosed = !drain && GetUplTopPlane(topz,topa)`。`drain` 为真时 C++ 短路，完全不调用该函数；也不进入使用 `topz/topa` 的顶部镜像构造（360）。不是“计算了平面但暂不输出”，而是不构造这类水力邻居。
- [载荷调用](../../../src/source/JSphCpuUpl.cpp:766)：`GetUplTopPlane(z,a,false)` 返回的 z/a 在后续载荷函数内不被使用，只使用成功与否。实际计算仅依赖 q(t)、固定 A0、owner 集合以及每粒子的 J/混合密度；没有当前表面法向、面积斜率或共面度。

没有找到其他 `GetUplTopPlane` 调用。该函数的平面几何判据与闭合期加速度拟合应分开理解；`acceleration=false` 本身不等于“排水开启”，需要实际阶段排水标志才能判断是否还要求镜像平面。

## 为什么竖向投影载荷不需要等高

每个受载 owner 的真实离散为

```text
V0 = MassFluid/rho0
A0 = V0/Dp
m_i = rhoMix_i * J_i * V0
a_load,i = −q(t) A0/m_i * e_z
F_i = m_i a_load,i = −q(t) A0 * e_z   （实际写回有 float 舍入）
总力 = −q(t) ΣA0 * e_z = −q(t) L * e_z
载荷功率 = −q(t) Σ[A0*vz_i]
```

这些式子不依赖各 owner 的 z 是否相同。[实现及总力误差保护](../../../src/source/JSphCpuUpl.cpp:774)

对单值上表面 z=z(x)，若 x 不变，竖向投影载荷是 `dF=−q e_z dx`，等价于按当前弧长的牵引 `t=−q n_z e_z`。**它不是一般法向压力**：法向压力给出 `dF=−q n ds=(q z_x,−q)dx`，会多出横向分量。非平面 TopVertical 可解释为竖向分布载荷/分柱加载，不能称为沿表面法向的流体压力，也不能称为始终保持接触的刚性平压板。

现有全土粒子累计横移保护仍有意义：A0 被当作固定投影权重。以 Dp=0.05 m、每粒子横移界 5 µm 为例，两个相邻列的间距误差最多是 10 µm，即 0.02%；它本身已经是有限容差的近似，不是精确不可横向变形约束。取消瞬时共面限制不应顺带放松这个横向条件或投影速度。

## 排水边界不使用平面，但依赖真实 mask

[排水时钟](../../../src/source/JSphCpu.cpp:1170) 对新 PR 使用当前 `UplStageTime`。实际排水 mask 由 [IsHydroMechDrainedParticle](../../../src/source/JSphCpu.cpp:1189) 决定：正常土中的自由面/孤立标记，排除特定 strip 模式；对于 TopVertical 不按平均高度或 top-owner ID 截取，也不检查 upward normal。

[ApplyFreeSurfacePorePressure](../../../src/source/JSphCpu.cpp:1364) 将这些粒子的孔压高低两部分都置零；PR 水力循环使用同一 mask，把它们当作 Dirichlet 邻居，不为它们推进压力率。每次力评估先更新自由面跟踪，再加载并施加排水值。[阶段调用顺序](../../../src/source/JSphCpuSingle.cpp:642)

因此不能把“drain 标志已开启”与“全部原顶 owner 正确排水，且没有内部误排水点”混为一谈。即使顶面共面，现有 guard 也未证明这两个集合相等。若以后按排水阶段取消共面否决，专项验收至少应核实：受载 owner 仍为真实顶部、所有预期顶部 owner 均被排水 mask 标记、无意外内部 FST_Isolated/自由面改变问题。保留正权矩的可行性/有限性/时间步保护；非共面邻域改变真实矩阵，不能要求它与平顶矩阵逐字节相同。

## 反例与必须保留的范围

- 封闭阶段非平面：仍用全局平均 z 镜像，会把通量边界放错位置；不能只跳过共面 guard 后沿用原公式。闭合期水平面和完整近顶加速度行检查必须保留。
- 倾斜表面要求法向压力，或刚性压板接触：当前纯竖直 A0 载荷不满足其横向牵引或运动约束，即使所有 owner 完整也不成立。
- 顶 owner 被埋入土中/不再排水、内部粒子误标自由面：只按 immutable ID 加载与动态排水 mask 可能脱节。单纯去掉共面检查不能证明边界正确。
- 大幅起伏/层交叉/悬垂：不再是近一维柱。全土初始 X 漂移、owner 缺失/重复、速度及位置有限性、穿面检查应保留；原来的平均面穿越检查本身仍偏严格，不能同时悄悄改成新自由曲面算法。
- `z_face=z_center+J*Dp/2` 依赖以 J 表示竖向厚度的近一维解释。顶中心 spread 与这个 mixed-face spread 不是同一量，OFF 的 38.6 µm 中心差不能直接当作新 PR 共面 guard 将必然失败的预测。

## 最小专项验收建议（本次未执行）

1. 同一固定 X、不可变 owner 的冻结列，仅在初始化后制造微小周期顶部起伏；选低于和高于旧 5 µm 共面界、但远低于 Dp 的两档。已排水时验证总力/功率符合上式、每个 owner 恰好一次、没有水力顶部镜像、没有加速度 fit 时间更新；不把运动算例物理精度等同于这个制造测试。
2. 使用完全相同起伏状态，在排水切换前与切换后的真实 Pre/Corr 时钟测试：封闭状态必须仍按原平面假设拒绝；排水接受必须同时验证 p=0 mask 与预期 owner/实际自由面一致。
3. 重放缺 owner、累计横移超界、非 finite、穿面及排水 mask 破坏的反例，确认没有把“跳过一个无用平面检查”扩大为吞掉真实几何或边界失效。
4. 平顶原状态逐字节回归；起伏状态则检验真实 PR 行系数有限性、正性/可行性及既有 dt guard，而不是与平顶强行相同。保留完整场的行内孔压/vz 差、横向动能、中心与 mixed-face 两种 spread，以判断仍可否作为近一维固结对照。

若以后实际触发，最小守卫分阶段建议是：

- 未排水或任一 top owner 尚未被实际排水 mask 标记：**保留共面检查**；mask 与物理预期不符时需单独报告，不能因为仍共面就视为排水正确。
- 排水已开启且全部 top owner 实际排水：才有依据将承载 owner/固定投影几何检查与不再使用的平面共面检查分离；仍保留全土横移、owner、finite 与穿面保护，不改变载荷方向或声称法向压力/刚性压板。

是否实施仍应由实际超限状态、上述边界语义和专项结果决定。本审查没有建议任何新的数值容差，也没有证明一般非平顶固结或滑坡顶部边界已经实现。
