## 确认并修复的 CPU 实现问题

原 `JSphCpu.cpp::InteractionForcesFluid` 把六个最终应力率写回放在 `shift || density_rate || acceleration || viscosity_metric` 条件之内。真实二粒子消费者场中，所有真实速度/应力/孔压为零，只给导数辅助速度一个切向分量：

`Lxz = (m_j/rho_j) b grad_z(W)` 非零，但 `tr(L)=0`、力=0、黏性=0。弹性 `sigma_dot_xz = G Lxz` 不应被跳过。该夹具验证消费者合同，不声称仅凭一个邻居能自己完成 MLS 重构。

| 实际交互检查 | 修复前 CPU Debug | 修复后 CPU Debug / Release | GPU Debug |
| --- | ---: | ---: | ---: |
| 2D/3D × 三种 SlipMode × 12 场 | 60/72通过，12个正/负纯剪切漏写 | 各72/72 | 72/72，memcheck 0 errors |
| 2D 正切向辅助试验的剪切率 | 0 | −75.200401 Pa/s | 同CPU |
| 3D 正切向辅助试验的剪切率 | 0 | −225.602280 Pa/s | 同CPU |

生产修改仅为将六个 `rsigma += rsigmap1` 移至原条件之后，与 GPU 的既有写回结构一致。没有改变应力率方程、精度类型、导数速度、C、边界、外载、积分器、DDT 合并条件或任何 XML 参数；这不是新一轮“双精度状态写回”改造。

前后72场中只有12个纯剪切的 `rsigma_xz` 数值改变，其余已记录消费者值相同。CPU Debug/Release 所有共享输出数值相同。CPU/GPU 的土粒子密度率、孔压率、加速度和黏性指标数值相同；应力率最大差 `6.103515625e-5 Pa/s`，在原阈值以内。这里是数值比较，不据此声称带 signed-zero 的逐位相同。CPU没有启动wall-receiver，GPU启动了，故不声称壁面receiver跨后端对照已完成。

最终还将封存的修复前CPU源码在私有目录按权威工程的默认语言标准重编译，用同一套当前完整Rebuild对象链接，不替换生产对象。新的72行消费者结果与最初诊断逐项一致，再次复现12个纯剪切失败；见 `../logs/bv_baseline_rebuild_r1.check.json`。因此写回问题不依赖早期MLS初始化所遇的对象失配推断。

## 真实 MLS / 阶段观察

当前完整 CPU Debug Rebuild、CPU Release 各执行固定水平 FreeSlip 的2D/3D夹具：2D208粒子、3D3328粒子，复用原生成XML/BI4，不修改它们。

- 切向平移及3D绕法向旋转的导数辅助速度最大误差均为 `9.313225746e-10 m/s`，原速度阈值不变。
- Debug/Release 摘要一致。3D的 MLS/解析辅助速度替换之消费者最大差为应力率 `.01146244 Pa/s`、孔压率 `2.22e-16 Pa/s`、密度率 `4.55e-13 kg/m3/s`。刚体转动校正应力率相对零参考的最大值 `.09169946 Pa/s`，低于原20 Pa/s地板。
- SPR和真实ct调用不改物理位置、速度/密度、double应力、孔压/p0、native IDs。
- `MDBCCorrector=1` 两阶段更新mDBC；设0时半步观察的 TangenVel 保持上一阶段值，但导数辅助速度仍刷新。该时层差异被记录，并未被本次修复消除。观察器只改变字段/InterStep，不推进时钟，不能冒称真实积分半步验证。
- 密度梯度仍是 raw，S/P可用C；即使导数速度相同，也不等于三个离散算子一致或力/应变率负伴随已获证明。

## 构建、失败保留与限制

默认 CPU Debug 构建、随后完整 Rebuild、CPU Release 和 GPU Debug 工程均成功。保留既有 `/Gm` 弃用、第三方缺PDB等警告；GPU伴随链接还报告既有静态库默认运行库冲突警告，实际 Debug 执行及memcheck通过，不把警告隐藏成“零警告”。GPU Release与服务器封存程序没有更新。

最早的测试脚本变量大小写冲突、Windows `max` 宏编译问题已在新夹具/构建脚本修正，未涉及生产物理。早期 MLS 初始化在增量对象下触发了原SPR准入guard；没有取消guard或采纳失败结果。完整Debug Rebuild后同输入的新标签检查通过；具体哪个旧对象失配未独立追溯，不将其认作物理不稳定。

所有旧输出及失败日志保留，新证据浅放 `tests/outputs/bv_*`、`tests/logs/bv_*`。伴随程序、对象、DLL在本地保留并以SHA绑定；它们不因源代码/CSV提交Git就被称为云端二进制备份。

本轮通过的是有限实现检查，不是新物理候选的全程验收。旧正式计算不是该CPU修复的全程回归。现有DDT1/2边界sentinel的CPU分两次/GPU一次累积差异单独登记，未在DensityDT=0夹具里验证或顺手改写。曲面、移动墙、倾斜NoPen、塑性/大转动和精确HG重启范围均未扩大。后续等待服务器三组Cryer返回后逐ν检查，不重开已暂缓的自重误差、Yao、滑坡、u-pl或TPI任务。
