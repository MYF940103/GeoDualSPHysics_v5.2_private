## Gated sequence

1. Freeze source and legacy GPU programs/runtime. Authoritative Debug/Release full Rebuild, then default-OFF native saved-output equivalence against the same GPU backend. Header/class-layout changes require a full rebuild; a successful incremental link is not ABI proof.
2. Private no-wall rectangular-periodic 2-D/g=0 fresh elastic state/lifecycle checks, initially k=0. Verify J/theta recurrence, sort/resize/periodic owners and poison tests; copied state equality is exact, but CPU/GPU arithmetic is not presumed 0 ULP. Use Debug memcheck and guard failures before trajectories.
3. Port full constant-k coupled momentum/storage/rate together, not just the Darcy Laplacian. Frozen manufactured affine/quadratic/accelerated-field comparisons and complete pressure overwrite must pass. Then actual periodic CPU/GPU coarse/half windows on the already used dyadic grid/sample times; retain original all-sample 5 Pa/.005 mm and normalized 1e-4 limits. Compare full XYZ/material IDs, stress/J and finite-window energy. Continuum/discrete errors remain distinct.
4. Add smooth k(J) only after constant-k OFF is exact against the newly frozen constant implementation. Use the existing exponential law, no independent k state/clamp. In the same pressure pass compute GJ and the complete alpha*k*GJ dot (Gp+rho_w*Ace) chain term. Reduce uk=(Kw/n)/gamma*alpha*k*|GJ| at the real force stage; reset OFF/k0/uniform cache to zero. Reuse the CPU frozen component/OMP-independent references, active-bound/rejection cases, nonempty chain/effect and actual compatible periodic coarse/half tests; scalar material values must not be retuned.
5. Walls last: only two opposing static parallel axis FreeSlip planes, equal dp/mass, tangential periodicity and zero gravity. Port the CPU nearest-node-anchored first-order reconstruction and Q parity for velocity, stress, C and physical acceleration; do not repurpose old mDBC pressure/viscous velocity as this closure. State before FS, reflected C after native C, physical acceleration after all native forces, then rate. Reproduce affine/noncoincident samples, reflection-negative controls, physical face flux/reaction, component identities and actual wall constant/evolving half comparisons with unchanged thresholds.
6. Only after private stages pass, review allowing GPU under the existing public master plus identical rejection/typed BI4/PART tests and synchronized docs. Until then the !Cpu public rejection remains intentional. Never advertise an old GPU executable as supporting these XML keys.

No 3-D, gravity, drainage/load, HG/SPR, NoPen/NoSlip, curved/moving boundaries, plasticity, shifting, variable-dt public mode, exact PART restart, tensor/discontinuous permeability or formal case is added by this plan. The known nonconservative Lstar/constant-neighbor consistency and explicit midpoint k=0 asymptotic limitations are inherited, not repaired by parallelization. Necessary local limits do not prove universal stability.

## Build and precision risks observed, not changed

- The authoritative solution is VS/DualSPHysics5Re.sln and its vcxproj. It imports CUDA 11.7, uses CUDA_PATH_V11_7, MSVC v143/14.36.32532 in the recorded successful recipe, compute_86/sm_86 and -use_fast_math. Do not replace this with another build system or silently change global math flags to force CPU equality.
- Cryer build r1 Debug failed with nvcc “A single input file is required for a non-link phase when an outputfile is specified”; its IntDir was under the path containing “Hydromechanic coupling”, and the nested /Fd/--keep-dir command quoting exposed spaces. The sealed r2 Debug/Release recipe succeeded using the same solution and a no-space C:/Users/syosh/AppData/Local/Temp/cryer_darcy_switch_build_r2/.../int/. This is a historical build-path fact, not evidence that a new GPU port builds.
- Keep separate isolated Debug/Release no-space IntDir and complete DLL/config copies; retain failed artifacts, binlogs and exact argv. An OutDir with spaces worked in that historical recipe; do not generalize that all nvcc argument paths are safe.
- Match CPU's deliberate double-versus-float operand boundaries in the new path. CUDA neighbor order/FMA/fast-math and float PosCell geometry can alter results; use declared cross-backend/independent-reference tolerances, not fabricated exact equality. Preserve same-backend OFF arithmetic.
- The local/server GPU model and driver must come from each actual run receipt, not a historical A6000 label. No hardware timing or speedup is claimed here.
