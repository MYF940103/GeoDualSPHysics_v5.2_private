# P3 isolated host-only build author

This is build-only author preparation. It has not run a compiler, program, help,
solver or reader. Root separately admits one configuration only after reviewing
the actual new P3 preparation. Existing P2 archives, canonical programs and C08
dependencies are protected.

The new context consumes the passed actual same-configuration P2 build and real
CL/LINK calls. It adopts the genuine P2 object order, SDK adaptation, library
search bindings, runtimes and authoritative VS project/solution. It does not
invent an old CPU Release build or reconstruct a missing library timestamp.
The P3 source must preserve 267 CPU / 270 GPU files, all shared/device ABI and
the unchanged Base.cpp; Single.cpp changes its host loop and both private headers
change. Base.cpp still needs recompilation because it owns those implementations.
Only Base/Single objects are replaced, retaining 84 CPU / 109 GPU objects.

The existing P2 environment, host compilation and ordered link functions accept
an explicit new P3 context and are reused without changing their module globals.
Their actual calls use the P3 tag and isolated output/IntDir; their error wording
does not relabel an old call as new. Numerical flags, CRT and dependency checks
remain unchanged. No NVCC or CUDA compilation is performed. Every new host must
consume the complete new source capture and both new private headers, with no
live or parent headers. GPU prefix/structure declarations remain unchanged.

`context(..., create=False)` is read-only inventory collection for a root
admission. Real build context checks freshness, then creates only its own private
output and no-space temporary IntDir. Two genuine CL and one LINK invocation are
recorded with actual native exits. Runtime copies follow a successful link.
Failures preserve calls, logs, source and partial outputs without retry.

Each build requires its own `upl_tpi_p3_build_r1.build_admission`, matching
configuration, `passed=true`, `build_only=true` and deduplicated stat inputs.
The public CPU/GPU solutions remain authoritative. DebugCPU is first; GPU Debug
checks the CUDA-adjacent host API. A build pass is not implementation, pressure,
stability, physical, full-cycle or production acceptance. No following action is
launched and no SHA scan is used.
