# CPU分面SPR二维固结短窗

2026-10-24。先验计划：原正式XML/BAT和历史结果不动；本测试在当前double应力/float孔压CPU程序上进行，HG关闭、NoPen关闭，保留Yao的材料、网格、加载、阻尼和排水设定。不将旧GPU10 s结果直接当作当前物理的真值。

四组使用相同dp=0.1、固定dt=2e-5（半步1e-5）、双精度位置输出、应力/孔压压缩梯度校正开启，0.02 s短窗、0.001 s保存：

- auto_off：原自动法向几何、SPR关闭，作为同程序控制；并非未经其他修正的旧正式模型。
- faces_off：保持同一粒子坐标，将底/左/右三面用mk明确分开并指定平面法向，SPR关闭；隔离法向/几何变化。
- faces_on：同faces_off，只开启SPR；隔离导数重构影响。
- faces_half：同faces_on，时间步减半；不因与控制相近就取代时间收敛检查。

三面必须核对生成边界点集/土粒子点集相同、mk归属和法向正确，不能只比较XML。每帧核验原生ID、有限正密度、无塑性/排除/穿墙、加载/排水集合和实际时间。半步孔压RMS差<=5 Pa、材料沉降差<=0.005 mm。完整加载之前合力使用实际斜坡目标；用原生质量/加载加速度检查，不把无观测值当作零误差。

通过后先审阅近墙/墙角压力、沉降、应力、加载及排水图，再决定0.1 s/更长风险窗。0.02 s不是完整二维固结验收，原一维100 Pa总应力均匀性限制不适用于非均匀条形荷载。Cryer是无固定墙的球体自由排水问题，不应强行开启SPR来假装验证曲壁。

新文件沿用`tests/scripts`（不另建support）、`configs`、`outputs`、`logs`、`figures`、`notes`浅层布局；所有入口拒绝覆盖旧输出。

## 0.02 s原程序结果与下一风险窗

四条原CPU程序均正常结束，原生土粒子20301（原网格含边界节点），三面前后点集相同。分面关闭SPR相对自动法向最大孔压RMS差6.384e-7 Pa；分面SPR开/关差0.22005 Pa。不是此时已证明SPR改善二维解，启动扰动尚小。

原输出触发使用累计物理时间，粗步部分帧晚20微秒、半步晚10微秒；实际时刻完全匹配的半步样本仅5个、截至0.004 s（0.043877 Pa、3.4266e-6 mm）。不插值原生状态，不宣称0.02 s全窗半步通过。新`spr_yao_step.cpp`仅按整数步调用原`ComputeStep()`/保存流程；先做0.02 s共同实际时刻原生字段0 ULP检查，再考虑0.1 s（到达斜坡加载结束）。源码积分与正式输出调度不改。

原严格x∈[-3,3]荷载有两端点原生ID8814/14874，在第一个正载采样前轻微外移，四组此后均只加载同一批59个内部顶层节点。因此离散载宽5.9 m、比理想6 m少1.667%；这是原节点式网格/严格范围的已有离散偏差，不能归因SPR或当作理想6 m合力通过。分析使用这59个材料点，单列端点和理想差值，不偷偷修改加载方程/正式网格。

0.1 s先验条件延续5 Pa孔压RMS/.005 mm最大材料位移半步限额；原生ID/无排除/弹性/正密度/无穿墙，真实斜坡载力和明确排水节点为零。非均匀条形载荷的应力空间变化应绘图量化，不套用一维均匀总应力门。若整数保存和原程序共同时间不逐位一致，先解释保存副作用，不继续长窗。HG/NoPen继续关闭，此项不是通用复杂边界或全程固结验收。

`spr_yao_grid02_r1`三条整数保存0.02 s完成：共同时间与原程序的字段0 ULP，粗步各9帧、半步5帧；没有声称原程序错时刻帧也被逐位核对。新的21个全窗半步样本最大孔压RMS差0.07057343 Pa，最大材料位移差0.00001137725 mm，均通过原限额。开/关SPR最大孔压RMS差0.2175903 Pa、总应力RMS差0.2299770 Pa，变化主要在近墙，短窗尚不能证明更精确。PNG/CSV和原生末帧表在`figures/spr_yao_grid02_r1_*`，审核收据在logs。

因此按上述先验准入`spr_yao_grid10_r1`三条新鲜0.1 s（并非10 s）；配置/BAT与输出使用独立新标签，仍不改正式根输入。0.1 s审查须与已验整数保存0.02 s的全部21帧做相同步长原生前缀比较，再核验101个全窗半步样本。原程序输出错时刻问题仅在测试保存机制中隔离，不改生产输出时间调度。

本轮默认CPU Debug最终构建退出0，case02日志`spr_planes_cpu_debug_final_r1.build.log`。0.1 s已有独立关闭/开启两条完成，半步正在运行；唯一一次性接续为`scripts/spr_yao_followup.py`，启动/等待状态见logs同tag的`.followup.launch/status.json`。核对本机`codex queue --help`及当前线程号一致后启动；只等待新序列并做离线分析/排队，不运行solver、不重启旧worker、不发连通性自测。审图和物理结论仍须由接续回合核验，不能把排队成功当作验收。没有本轮新Git提交或GPU源码修改。
