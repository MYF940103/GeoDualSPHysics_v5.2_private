# Cryer旧记录实际时间步与当前启动的区别

2026-10-27只读核对。复现脚本：`tests/support/cryer_dt_history_r1.py`；
检查收据：`tests/logs/cryer_dt_history_r1.check.json`。不修改或重跑旧结果。

旧根输出`CaseCryerProblem_PR_out`实际记录为2026-06-22、305807步、
最终原生时间0.9109307138662156s。Run.out/生成XML虽然标注FixedDt=5us，
**不能**把这个配置值乘步数，当成全程实际时钟。

CPU/GPU的Git提交`8af9ed55`（2026-07-03）均将
`if(FixedDt)...; dt=min(dt,dtw);` 改为
`if(FixedDt)...; else dt=min(dt,dtw);`。
因此旧版本会在FixedDt之后再限制dtw，当前版本固定步不自动裁剪。
当前审计复算dtw=2.9787699190438848us。

本次独立读取旧PART1和PART1000、核验旧审计绑定的SHA及零基Step：

| 旧PART | 原生时间(s) | 零基Step | 5us首步+Step×dtw 与保存时间差(s) |
| --- | ---: | ---: | ---: |
| 1 | 0.0009135248253083916 | 305 | 6.72e-18 |
| 1000 | 0.9109307138662156 | 305806 | 3.08e-12 |

两点均符合首步5us、随后约2.97877us的累积；没有逐一审计旧全部1001帧，
也不声称逐步0ULP复制。当前Debug200步的5us固定步诊断，不是这个旧运行的
实际步长复刻。以后若比较新旧结果，应使用原生实际时间，明确步长和其他版本
差异，不能将差别仅归因应力double；也不能用当前5us超dtw来解释旧6月结果。

## 仍待区分的启动效应

本代码保留惯性，从零孔压/零速度突然施加载荷；经典准静力Cryer中心曲线则
以p(0+)=q开始。均匀、小应变、近似无排水连续体极限下，
M=Kd+4G/3=2.692308MPa，Kw/n=666.666667MPa，
Mu≈669.358974MPa，sqrt(Mu/rho)≈564.573m/s，R/c≈88.56us。
实际代码Cs0只取骨架M，对应35.805744m/s；它不是这个条件性耦合快波估计。

约0.1ms传播尺度与旧Tv=.0001约91us接近，仅是惯性启动的一条线索；
不构成离散谱、稳定时间步或振荡根因证明。球面反射、显式扩散、阻尼及离散
都会改变波形。旧中心压力2.7045q与本轮0.25ms全场最大19820Pa不是同一点、
同时或隔离A/B，不能混用。有限Kw对应的均匀无排水B≈0.997506，也不足以
单独解释倍数启动峰值。

源码位置：`JSphCpu.cpp`的弹性应力率、孔压压缩源、动量/速度更新和
`DtVariable`；`JSph.cpp`的`ConfigConstantsSoil`；文献u-pw节4.2式46–47。
这些解释只确定后续受控比较的方向，不构成任何新的物理修复或Cryer验收。
