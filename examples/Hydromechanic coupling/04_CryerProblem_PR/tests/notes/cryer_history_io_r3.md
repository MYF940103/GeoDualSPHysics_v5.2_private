# 第 64 步末帧的上一完整步孔压

在保留的 C04 CPU 和 GPU B64 末帧上，私有程序以原版 `JBinaryData` 写入可选压力历史，关闭文件后重新读取，并用 `JPartDataBi4` 的常规 PART 读取入口复核 22 个原生数组。两个后端各 37,173 个土粒，按原生槽位和重排槽位各核对一次下一步预测，双精度预测值与 float 写回逐位通过。

## 时间和所有权

两份 B64 的 `Part_0001.bi4` 对应已完成 64 次更新，原生零基 `Step=63`，时间为 0.0001220703125 s。此时当前压力是第 64 步最终边界处理后的原生 `PorePress`。第 64 次更新的真实第三轮记录中，`pn_Pa` 对应其起点（第 63 步），`previous_Pa` 对应第 62 步。保留的 GPU CommitKernel 在最终边界复核后执行 `previous[id]=rows[id].pn`。本测试从各自后端的同一完整提交重建第 63 步压力，并逐 ID 核验第三轮的最终值与原生末帧。

私有格式是在 `PART_0001` 下增设 `TpiPressureHistory` 子项，其中存材料 ID 的 uint32 数组、上一完整步压力的 float32 数组，以及格式版本、压力时间算法、有效标记、RunCode、已完成步数、当前及上一时刻、固定 dt。存储时历史 ID 故意逆序。读取时按历史 ID 与原生 `Idp` 对应，再在原生顺序和另一种反转移位的顺序下调用共享 `TpiPressureRow.h` 的预测函数。两份历史均增加 297,760 字节，含 ID、历史压力和子项元数据。

| 检查 | CPU B64 | GPU B64 |
|---|---:|---:|
| 当前原生压力与第三轮最终压力相同的材料 ID | 37,173 | 37,173 |
| 两种槽位顺序中逐位通过的下一步预测 | 74,346 | 74,346 |
| 误用第 62 步压力时得到不同预测的 ID | 37,173 | 37,173 |
| 误用初始保存帧压力时得到不同预测的 ID | 37,173 | 37,173 |
| 将上一压力冷启为当前值时得到不同预测的 ID | 37,173 | 37,173 |
| 保持相同的原生数组／根元数据项／PART 元数据项 | 22／33／27 | 22／33／31 |

## 读取语义与兼容

- **有历史**。先验证算法、格式、原生时钟和固定步长，再验证所有有效材料均有且只有一个有限的上一压力。允许缺历史时冷启的接口在有效历史存在时也会优先恢复。恢复构造新返回值，所有验证通过后才能交给调用者。
- **没有历史**。要求恢复真实上一时间步的读取返回失败。调用者明确选择冷启时，程序返回冷启状态，并将本步原生孔压作为上一值。分别验证了初帧与已有 64 次提交的旧末帧。
- **历史损坏**。16 组故障涵盖有效标记、版本、算法、RunCode、已完成步数、dt、当前时间、前一时刻（含单 ULP 扰动）、数组缺失、类型和长度错误、重复 ID、边界 ID、非有限压力及缺少版本字段。每份畸形数据均经过 JBinaryData 内存序列化和重读，对要求恢复和允许缺失时冷启的两种策略都拒绝。另测试了目标原生 ID 重复。原库会给缺少版本字段的两次预期失败各打印一条异常，随后继续运行其余检查。
- **默认 A**。私有读取入口不分配压力历史，不访问 B 子项。另取两个后端的原始 A128 末帧，以原生库重写的文件均与输入整文件 SHA-256 相同。将 B64 派生文件中的私有子项移除，再序列化，其完整字节也恢复为对应保留输入。所有源文件在运行前后的 SHA-256 均相同。

## 范围与复现

该试验使用原生文件格式在主机上读取两后端的既有结果。输入限于 C04 单片、固定材料集合、无排除和无 ID 复用的固定步长末帧。真实求解器的保存／恢复钩子、GPU 回填、后续粒子退休、非定步长及其他积分器或 HG 状态仍在本次范围之外。此结果只验证压力历史序列化和下一步预测输入。
