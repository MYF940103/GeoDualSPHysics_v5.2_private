## Why the previous figure lacked small Tv points

The previous full run used `TimeOut = 0.0025 s`. Since the current conversion
gives `T_v = 0.02744` at `t = 0.0025 s`, the first saved post-origin sample was
already too far to the right on the log-scale paper axis.

This dense-output run reduces `TimeOut` by a factor of 10. The first saved
post-origin sample is now:

- `t = 0.00025 s`
- `T_v = 0.002744`
- numerical `p^w/p0 = 1.04594`
- theoretical `p^w/p0 = 1.06788`

To place the first numerical point near `T_v = 1e-4`, `TimeOut` would need to be
about `9e-6 s`, which would produce more than ten thousand full-cycle output
frames and is not efficient for the current validation pass.

## Current conclusion

The missing small-`T_v` points in the previous figure were caused by the large
post-processing/output interval. With `TimeOut = 0.00025 s`, the early Cryer
development is visible and the full-cycle accuracy is essentially consistent
with the coarse-output full run. The apparent increase in maximum velocity is
an output-resolution effect: the denser run samples the initial transient that
the coarser run skipped.
