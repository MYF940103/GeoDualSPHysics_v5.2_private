# Host loader policy component (prepared, not executed)

`support/upl_material_loader_negative_r1_build_run.py --execution-authorized` is one explicit root-reviewed host compile/link/run, not a solver. It consumes the new r3 DebugCPU 85 non-main objects and the passed `upl_material_release_native_r1_source_CPU.native.check.json`, specifically its genuine Version2 Part0010. Source/header/object/runtime stat bindings are checked before and after; no SHA scan is used. All outputs are fresh under `outputs/upl_material_loader_negative_r1`, with cases n1..n5 holding standard Part0010 names. Original source/BI4/programs and old tools are untouched.

Six actual cases: qualified positive import; unknown uint version3 while typed old MR1 remains; wrong float version2 while typed old MR1 remains; unknown handoff schema99; required Kplastic renamed while all22 array payload bytes remain unchanged; real JPartsLoad4 generic PART load with Version2 and one serialized nonzero kappa=.125 sentinel. Each rejection must match its actual first cause, not merely a nonzero process exit. The generic path must report the material-law rejection before later dynamic-state checks. PRE calls use actual JGravityPreloadState::Load; generic uses actual public JPartsLoad4::LoadParticles directly, with no JSph scene or admission shortcut.

Metadata-only fixtures retain every array payload byte; the required-array negative only changes the array name, preserving its typed count/data. The generic fixture deliberately changes one kappa value in its new copy; it is invalid test data, not a newly qualified PRE and is never published as a checkpoint. Its actual serialized nonzero value is independently read before the generic call. Original source whole-file bytes and all fixture bytes/payloads must remain unchanged during loading.

After generic throws, its newly allocated internal buffers may be uninitialized. The component never reads them and does not claim atomic restoration of loader memory. The supported conclusion is an actual refusal before copying/accepting a restart and preservation of file-backed history, not a resumed or complete-state calculation. No half, physical step, long sequence, physical acceptance, or automatic retry follows.
