# C08 私有 cached HG 效率：只读审查

审查对象为已冻结的 `c08_h18_hg_cached_r1.cu`、两个生成 host 及其实际构建记录。审查没有运行 profiler、GPU 组件或额外求解器，也没有修改当前 .90s 窗口的任何依赖。以下是源码可确认的工作量及候选方向，并非实测瓶颈或速度倍数。

每完整更新，私有路径有 33 次 kernel launch（其中两次替代原积分核，因此不能全部称为新增）、11 次小型同步 D2H（2 次 Summary 与 9 次 Failure），以及 5 次 Map 的错误清零和 ID-map 清零。`cudaGetLastError` 不是设备同步。Release 保存仅写已在 host 的小型阶段汇总，不是每个 force 阶段下载全图。

优先候选：

1. 多个 kernel 每个有效粒子对同一个 `fail->bits` 执行 `atomicAdd(...,0)`，每完整步约十万次同址原子轮询。可研究每 block 一次原子快照后广播，但所有线程必须先到达 block 同步，不能把同步放在已有提前 return 之后。错误标志、首因和提交前全局拒绝仍须保留；无错误时不得改变物理算式。优先保留材料 producer 本身的编译数值体，避免再次引入材料求值语境变化。
2. 小型同步查询可研究合并控制包，完整保留 Failure 的 ID/detail/value。不能跨越 force 提交、cache 消费或完整步验收的安全边界，不能降低检查频率。
3. 每 stage 的最终单线程归约仍串读 5000 份 PartialSummary。可研究汇总字段瘦身或分层归约；如果改变观察量的求和次序，必须明确其诊断位差与预算，不能继承旧观察量逐 bit 一致声明。物理 force/e 不应受此影响。
4. 邻表实际 cell 遍历、最多 128 项插入排序、reverse/history 二分检索以及 Row/Node 的多轮读写也可能有开销。热冷字段分离和减少只改一项却整结构写回，比跨 stage 复用旧几何、LS 或邻表风险小。不能为效率改变 native-ID 累加次序或冻结变化中的拓扑。

已经避免的开销：持久数组仅首次分配；完整步历史通过三个指针交换提交；没有每 force 分配或全图 D2H；Release 不下载 Debug 首 n 快照；原 Darcy 每 force 仍只执行一次；材料返回已经是唯一 producer，不应恢复重复求值。

当前先保持物理窗口不变。只有物理结果值得保留时，才选择一个最小优化候选，建立新标签并验证实际执行。既有 OFF 全 22 数组/时钟位证明和首 n 独立 CPU 力证据可作为保留基准，不能直接证明重新编译后的程序；任何证据传递都必须有实际完整输入与输出相等，或重新完成相应比较。不得把默认关闭兼容性、首力或两步弹性检查外推为全塑性窗口、耦合能量或三组正式物理验收。
