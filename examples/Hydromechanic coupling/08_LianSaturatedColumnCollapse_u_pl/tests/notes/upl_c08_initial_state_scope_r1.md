# 初始水头与重力预平衡：只读准备

2026-11-06。Lian2023 §4.4及图13要求保留右墙、施加重力建立原位总/有效应力，再撤墙；未给定预平衡时长、收敛指标，也未说明静水压力是先赋值还是由零增长。Ref2021的3 m非饱和入渗土柱（水位在底部、初始h=-z）不是本例的机械重力预平衡说明，不能直接套用。

当前实际初始化语义：

| 模式 | p/p0 | 有效应力 | J/n历史 |
|---|---|---|---|
| None | fresh时均为0 | 0 | observer单独置J=1、theta=0 |
| ConstantZ | 按给定水头面的静水p，并令p0=p | 保留fresh的0 | 不因赋值而变形 |
| AnalyticalSelfWeight1D | 静水+有限Kw未排水超孔压 | 同一未排水分配 | 不是排水平衡或已沉降历史 |

实现见 `JSphCpu.cpp::InitHydroMechState`、`JSphGpu.cpp::InitHydroMechPorePressure`，以及两端Single的fresh初始化。解析1D模式用M=K+4G/3、B=(Kw/n)/(M+Kw/n)，分配p_ex=B*(rho0-rhow)*g*d与sigma'_zz=-(1-B)*(rho0-rhow)*g*d；应力初值先按float计算再提升到double状态。不能把它称为直接赋排水平衡场。

当前dynamic容器仍仅准入InitNone。后续若测试静水预填，须单独核对原有ConstantZ路径与J参考/边界的一致性，使用图13物理水头面H=2 m，不能拟合为1.98 m粒子中心来追求吻合。静水预填可以减少冷启动水力瞬态，仍须验证力学平衡及实际J/n/κ历史，不能据O(N)初始化跳过重力过程。

现None启动的native p0始终为0；其p-p0不是论文以初始静水场为基线的超孔压。后续塌陷图需明确原始p0与另行声明的物理参考，不修改原生数据冒充两者相同。

当前dt2^-18需要每物理秒262144步。短窗Debug GPU的线性预算约5小时/物理秒，只能作Debug成本尺度，不能预测预平衡所需物理时长，也不是服务器Release测速。必要长程、多组及敏感性计算仍按用户要求打包到服务器；在边界/材料/初始应力准入完成之前不启动冷预平衡长链。

本记录没有修改配置、初始场、源码或求解过程，也不构成平衡/塌陷验收。
