# Causal window scientific extraction — author only

New `support/upl_c08_causal_physics_r1.py` is only authored/AST checked, not imported or executed. It requires the genuine passed `upl_c08_causal_window_GPU_r1.trace_review_r1.json` and `.native_r1.json` before opening data. No checker, decoder, BI4/VTK, solver, build or queue is invoked. Existing outputs are protected; fresh products are three matching CSVs (`stages`, `totals`, `native`), two PNGs (`history`, `dense`) under tests/figures and one tests/logs JSON, all with prefix upl_c08_causal_physics_r1.

The main97-column CSV is streamed exactly once, keeping only the current sampled-step group in memory. One wide row per sampled step/ID records the actual context time/step, p_n/half/full-raw/final-ponded, both FS branches, five RHS terms, material status/Ibase/Itrial/Ireturned/K/kappa, Jbase/Jhalf/Jnew/theta and plane hit/clamp/before-after velocities/delta-v/delta-move. Leading and all trailing ponding records are preserved as compact JSON lists in that row. Plot memory contains only selected numeric columns. The three IDs are7017/5944/6814; the original every40/dense sampling is identified, not resampled. All x coordinates use actual step_start_s minus the actual imported PRE clock; native points retain their actual save clock. No substage clock shift, interpolation, smoothing or FFT is added.

For each actual RHS stage the five Pa/s terms are: compression=−(Kw/n)theta; LP=(Kw/n)(ki/gamma)LP; defect=(Kw/n)(ki/gamma)[rho_w Ai·Lx for FS2/3, otherwise −GpCorr·Lx]; divAce=(Kw/n)(ki/gamma)rho_w divAce; chain=(Kw/n)chain/gamma. Here Kw=1e9, rho_w=1000 and gamma=rho_w*9.80665. The logged lap/value/rate and original budgets have already been certified by the checker. This extraction does not repeat those gates or mix divAce into the defect. It reports actual finished-Ace terms, not an independent force split into AS/AV/stress channels.

Material/plane ordering matters: Pre RHS → pressure half update → Pre return → Pre plane → Cor force/RHS → Cor return → Cor plane → full pressure update → completed ponding. The Pre return can affect Cor force. Same-step Cor trace drop occurs after Cor RHS and cannot explain a value already formed; Cor plane does not rewrite that Ace/RHS. CSV records both stages rather than assigning that false causality. Status-onset flags require consecutive actual sampled steps; a gap of40 is not certified as a resolved transition. Trace drop/(3K) is explicitly a constitutive trace-reduction diagnostic, not a complete independently measured plastic-volume tensor/history.

Only the genuine56-column Totals contains every actual Cor and plane update. All original counters/statuses/zero hits/zero delta-v, initial/returned traces, base_trace_changes and endpoint residual/budgets are retained. Derived interval differences use successive saved cumulative endpoints (first interval starts at the actual zero accumulator), never sparse sampled-source integration. Sum dt theta, sum log(Jnew/Jbase), sum dt trace(stress rate)/(3K) and sum material trace drop/(3K) remain distinct; no new sigma-J identity or pressure-budget tolerance is imposed. Passed budgets come from the original checker. Native typed data is a fixed6805/22/90 memmap view; only three selected IDs at90 actual saves are extracted to anchor pressure/J/kappa/Ieff/position/velocity/FS, without another field decode or full-body analysis.

The history PNG separates pressure phases, five corrector RHS terms plus the actual total RHS, actual J/returned effective-stress trace, and full-step Totals. The dense PNG shows the actual .79–.81 and .83–.85 windows with pressure and Pre/Cor trace drops; J stays in its separate history panel so it cannot hide the much smaller single-update trace drops on a shared scale. It draws plane-hit markers only when actual hits exist. Both retain raw extrema; RHS uses a labelled symlog display only. Full-step zero contact evidence stays zero: it excludes direct plane updates to these three IDs, not contacts of their neighbors or a global contact influence. JSON extrema/first observed statuses are qualified as sampled, while final Totals are full-step cumulative. Three-ID ordering is evidence to interpret, not proof of a global cause or physical acceptance. Source size/mtime is checked around extraction; no hash scan is used. Root reads the complete source/note before one explicit execution.
