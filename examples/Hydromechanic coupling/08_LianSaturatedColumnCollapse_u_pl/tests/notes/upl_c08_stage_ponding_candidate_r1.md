# Released-substage positive-pressure projection candidate

This is an unvalidated numerical candidate. Only JSphCpu.cpp, JSphGpu.cpp, JSph.cpp and the existing FreeSeepage XML comment change. No XML switch, kernel, array, integration formula, public admission range or wall fit threshold is added. No build, solver, decoder or accepted-result replacement has been performed in this author task.

The existing completed-geometry projection remains literal. Its boundary-entry gate additionally admits a half state only when HydroMechFreeSeepage, HydroMechDynamicSeepage, PorosityFeedback, GravityPreload and GravityPreloadReleased are all true. The unchanged CPU loop / GPU ponding kernel sets finite positive pressure to zero only on normal native FS2/3 soil. Negative pressure, nonfinite canaries, P0, rate, J/theta, effective stress and kappa are not written by this projection. The Shepard entry's separate !PorePressPre gate remains unchanged; preload Shepard is already disabled upon release.

Actual order is Pre -> half RunCellDivide -> ApplyPorePressureBoundaries: wall state -> native FS/C -> wall C -> positive-pressure projection -> next Interaction_Forces. That force already refreshes wall state and native FS/C before AS and momentum, and then completes Ace before dynamic Darcy. Therefore the wall pressure used by force reflects the projected half soil pressure without an added wall-neighbour pass, force pass or FS pass. Under the admitted static geometry/no-shift/no-moving/no-inout path, wall J/active geometry and the repeated FS/C classification are independent of pressure; p is a separate fit right-hand side. A short implementation check must still demonstrate that the half boundary mask and the following force mask agree and the wall read has refreshed, rather than claim bit identity from this static argument alone.

PorePressPrec/PorePressPreg is the saved p_n corrector base. Projection writes only the current p_h buffer. The unchanged corrector forms float(p_n+dt*rate_half), not projected-p_h+dt*rate_half. Predictor and corrector sorting continue to move p and p_n together. Do not copy the projected half pressure into p_n or remove its old protection in any checker. A completed-only trace checker must explicitly recognize the additional genuine half PONDING events and preserve the original update/base checks; it must not skip unexpected rows or relabel half records as full steps.

Before release, GravityPreloadReleased=false, so a live Pre pointer still prevents half projection. The existing source PRE file, source contract, source mathematics and normal completed-step policy are untouched. New dynamic-feedback gravity output identifies FreeSeepagePondingPolicy="ReleasedSubstages" and FreeSeepagePondingActive=GravityPreloadReleased; this inactive policy description can be present in newly generated pre-release metadata and is not a claim of byte identity of new output headers with old source files. Original certified PRE bytes are not rewritten.

The Run.out description explicitly calls the policy a candidate without physical acceptance. FreeSeepage remains disabled by default. The XML guide changes only its explanatory comment, retaining all parameter values and existing admission restrictions.

This changes boundary timing in a projected explicit midpoint method. It may affect order, pressure storage/discharge, the pressure RHS and AS through total stress sigma_eff-pI; no flux conservation or coupled stability improvement is asserted. It preserves negative pressure and does not implement Lian's separate negative-pressure stabilization. Existing FS0 pulses also mean a surface projection cannot be assumed to remove all pressure growth. Keep original finite/domain/ledger/clock/ID/P0/wall/plane checks, and do not treat lower peaks, normal exit or the n3 comparison as physical validation.
