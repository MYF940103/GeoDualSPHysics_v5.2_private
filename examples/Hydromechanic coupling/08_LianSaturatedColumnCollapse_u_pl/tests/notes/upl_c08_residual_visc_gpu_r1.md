# Private actual-GPU matched residual-viscosity candidate (author only)

This candidate is a new instantaneous numerical momentum operator, not GNOG, shifting, the existing artificial viscosity, or a physical acceptance. Only three private copies from the frozen `upl_c08_bedkeep_source_r1/source.zip` change: `JSphGpuSingle.cpp`, `JSphGpu_ker.h`, `JSphGpu_ker.cu`. They, `residual_viscosity.patch`, `source.json` and a complete small source ZIP are under `tests/outputs/upl_c08_residual_visc_gpu_r1_source`. Production sources, projects, runtime_r5/r6, inputs, PRE, programs and old outputs remain untouched. No compile, helper, solver, native decode, force evaluation or numerical test is executed by this authoring task.

Both host/CUDA TUs require `C08_RESIDUAL_VISCOSITY_CANDIDATE`. Without it, removing the guarded additions recovers all three original archive members byte-for-byte. No class, CTE, persistent GPU member, existing function signature or public XML parameter changes. A second private compile macro, `C08_RESIDUAL_VISCOSITY_ALPHA0`, sets alpha=0 and skips the entire numerical helper: no candidate allocation, kernel or Ace write. Its policy is explicitly inactive and actual Pre/Cor counters stay zero. OFF byte equivalence is still a future actual-program check, not inferred from a successful build.

ON is limited to released, certified-handoff C08: 2-D nonperiodic Cubic, Symplectic fixed2.5us, 6805 current particles/1805 fixed/5000 normal soil IDs2060..7059, keep5 fixed-plane contact, original total-AS .2/n3 and AV .1, release Shepard/damping OFF. No PRE work is performed by the new operator. Invalid scope rejects rather than silently applying another graph. Softening history is not used to rescale the fixed positive elastic G. Plastic localization can be damped by this numerical operator; that risk is not a precision improvement claim.

Pre-build author-only scope correction: the first uncompiled draft also tested `NpbOk!=Npb`. That condition alone was removed before any actual-GPU candidate build. `NpbOk=Npb-GetNpbIgnore()` can legitimately exclude distant fixed bed nodes from active boundary work while all6805 native particles/1805 fixed roles and the full5000-soil graph remain present. A soil-only operator with no wall bonds does not require every fixed node to be active. This does not relax any rank, finite, damping-bound, material, hydraulic or original boundary guard; header/CUDA numeric code and all other scope conditions remain unchanged.

The hook is after original mechanical/AS/AV/DEM contributions and the original2D Y reset, immediately before `ComputeDynamicPorePressureRateGpu(dynamicridpg)`. The original wrapper subsequently reconstructs current wall Ace and computes dynamic Darcy from finished Ace. There are no fixed-wall bonds, but wall/FS pressure responses through the original Darcy wrapper can change. The candidate does not directly write positions, velocity, pressure, P0, J, theta, stress, kappa, C, FS or wall roles.

The two kernels reuse `cunsearch::InitCte` and `ParticleRange` on the existing **fluid** cells. They share one pair predicate and traverse the full same support in each pass; no neighbor cap, all-pairs scan, FS exclusion or C-matrix substitution is introduced. Distances use original global double x/z; support is the matched CPU strict r^2<4*h_float^2, with the original CTE Cubic float fac evaluated at float(r^2), w=-fac. Distinct coincident nodes, nonfinite states and invalid roles fail. Actual V=(MassFluid/RhopZero)*J and rho=rho_w+(RhopZero-rho_w)/J are recomputed from the same current J. Tau=h/sqrt(G/rho), eta0=G*(tau_i+tau_j)/2, and beta0=eta0 Vi Vj w. Native-ID ordering makes the beta0 multiplication order reciprocal. LS uses eta0 Vj w; alpha and receiver Vi cancel only from LS.

Fit stores four double x/z entries of L=N M^-1. Its scaled unregularized2x2 condition is a>0,c>0,det>128*DBL_EPSILON*(a*c+b*b), matching the CPU/math candidate: no ridge, skipped receiver or fallback. Force is -alpha/2 sum_j beta0*(vij-Li*d+vij-Lj*d), divided by actual rho_i Vi, then added to original float Ace through one double add/float cast per node. Y is preserved from the original reset. Error arrays for fit and final force are separate, so the second kernel only reads immutable fit errors.

The host helper owns RAII-local CUDA allocations for L4, lambda, candidate float3 Ace, fit/final error arrays (about300kB for5000 nodes), plus host error/lambda vectors. It launches exactly two candidate kernels, downloads all final errors and lambda, rejects any rank/role/finite failure, and requires dt*lambda_max/2<=1. Lambda_i=2*alpha*sum_j beta0/(rho_i Vi) already includes alpha once. This is an isolated frozen damping sufficient bound, not full u-pl stability. Only after **all** checks pass is candidate Ace copied once device-to-device onto the5000 soil slots. No candidate kernel writes Ace in place. Scratch is freed on helper return, before the original Darcy/wall-Ace wrapper; no global GPU destructor/reset is added. Existing base force/wave/pore/gradient dt guards remain unchanged. The per-stage allocations, copies and synchronization have a real performance cost and have not been benchmarked.

Typed sidecar `C08ResidualViscosityPolicy.json` records the private policy/alpha/active status and explicitly says `BI4_metadata=false`, `native_22_schema_changed=false`, `PRE_contract_changed=false`. It is **not** PART metadata and the unchanged native reader cannot validate this new operator. `C08ResidualViscosity.csv` is26 columns: record,phase,active,alpha,step_start_global,completed_global,step_start_time_s,force_stage_time_s,save_time_s,operator_dt_s,phase_calls,phase_commits,pre_calls,cor_calls,pre_commits,cor_commits,last_lambda_max_s_1,running_lambda_max_s_1,last_dt_lambda_half,running_dt_lambda_half,validated_soil_nodes,committed,error_bits,invalid_sorted_index,invalid_native_id,cuda_status.

Counters increment on each actual ON helper attempt, separately for Pre and Cor; commits increment only after successful Ace copy. Counter order is checked, never inferred from saved frames. Normal SaveData appends the latest actual Pre and Cor records with current cumulative counters (normally each4000 updates and final-only smoke/final output). Completed global=Nstep+1 and save_time=actual TimeStep are read after the original full update/outer scalar increment. Stored force start is actual TimeStep from the earlier force call; Pre evaluation is that t_n, Cor evaluation is t_n+dt/2. No n*dt clock replacement occurs. An OFF save row has phase OFF, counters0 and inapplicable zero force-time/dt placeholders; it is not a fabricated stage call. Rejection additionally appends an immediate failure row with completed_global=Nstep (old completed base), explicit actual phase/ID/error/CUDA status, then stops. Observation I/O errors also stop rather than claiming complete evidence.

Error bits are input1, coincident2, weight4, rank8, nonfinite fit/lambda16, invalid neighbor fit32, nonfinite force/commit64 and isolated-bound128. A mathematical rejection leaves Ace unchanged by the candidate; prior original force/wall work is not rolled back. CUDA failures preserve their actual nonzero API status. The ordinary physical exception channels are not bypassed. The policy/counter sidecar is unique to the fresh output directory and refuses existing candidate sidecars at first initialization.
