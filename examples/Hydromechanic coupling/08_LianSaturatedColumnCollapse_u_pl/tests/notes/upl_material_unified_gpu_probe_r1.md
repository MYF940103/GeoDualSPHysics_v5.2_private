# Unified material CUDA component r1

Author-only files: `support/upl_material_unified_gpu_probe_r1.cu` and `support/upl_material_unified_gpu_build_run_r1.py`. No build or execution has occurred at authoring. The immutable combined header is reused; no production source, native adapter, server package or engine objects are changed. After root full review, the single command is `D:/anaconda3/python.exe -X utf8 -B tests/support/upl_material_unified_gpu_build_run_r1.py --execution-authorized`, with the case08 root as working directory.

The component contains 69 inputs in one CUDA batch: 18 constant smooth and 18 genuinely evolving smooth points (each group includes nine rotated tensors), 18 evolving apex/explicit tension-repair points (all three fits/three psi signs with zero or nonzero trial q), four phi-zero cylinders (constant/evolving and rotations), two elastic points, two explicit old-threshold witnesses (trial F approximately 5e-6 and 2e-5 Pa), six invalid inputs, and one deliberately uncertified soft path. There are 20 rotated points, 24 same-device constant-law two-entry exact checks, and seven failed-state scalar-bit checks. The independent proper rotation is the rational orthogonal matrix with rows `(1,8,4)/9`, `(8,1,-4)/9`, `(-4,4,-7)/9`; rotated smooth tensors have all six components.

All manufactured expected traces, q values, multipliers and continuous histories use separately written exponential laws and the published PS/C/MC coefficients. Device results are checked against those fields, compliance-derived deviatoric kappa and volumetric strain, smooth flow or apex subgradient, yield at continuous kappa, saved float-kappa cast bits, and rotation covariance. Original CPU component budgets remain: stress `5e-10*scale+1e-8` Pa and strain `2e-12+2e-10*max(abs(lambda_s),abs(lambda_t),abs(delta_kappa))`. Elastic points retain the existing `F_trial<1e-5 Pa` policy, so the small positive-yield elastic witness is not incorrectly forced onto the yield surface. Saved-float-history yield residual is recorded separately, not compared with continuous root residual or called spatial accuracy.

Host evaluation of the same U entry is an implementation control, not an independent theoretical reference or proof of separately compiled MSVC equivalence. Both host and device are checked against the manufactured/compliance reference; their differences use the sum of their original per-evaluation budgets. Fixed-law basic/soft entry exactness uses coefficients generated on the same device by `U::UpdateDPvars`; host/device trigonometric or exponential rounding is not forced bit-identical. The completed actual CPU 109-point receipt binds the shared header as a prerequisite, but this is a new smaller case set, not a relabelled CPU data replay.

The kernel receives only POD input state/material/fit and writes result PODs. Every declared input scalar, including invalid NaN bits, is checked unchanged; both failed host/device states preserve their own input scalar bits. Two output-tail slots compare every defined Result member, never padding. The runner makes one standalone CUDA11.7/MSVC14.36 Debug sm86 build with the project's `-G -g -use_fast_math`, static cudart and `/Od /MTd` settings, then one compute-sanitizer memcheck with true retained tool/target Win32 exits and zero errors/leaks. Static cudart and static Debug CRT need no copied runtime DLL; the installed NVIDIA driver remains required. This does not consume a prior project CUDA object closure, launch a spatial solver, add a half-step chain, or accept a full collapse calculation. UnresolvedPath remains an explicit algorithm limitation.
