# AS/fixed-plane summary repair and offline CPU adoption

Author-only additions; no solver, decoder, build, queue or script execution was performed while preparing this repair. The original r1 owner, original note, failed run receipt, stdout, Run.csv and native data remain unchanged.

The one CPU smoke actually completed 40 updates, global step 4000040 and one saved frame with Popen/Win32 solver exits zero. Its r1 owner then failed while reading Run.csv: Configuration contains the unquoted token `AS_Bui2008(0.2;2.55)`, so the semicolon split produces 44 values for 43 header columns. This is a post-run parser failure, not a failed physical target. The actual coefficient/exponent log uses `=` whereas the r1 owner expected `:`.

`support/upl_c08_asplane_summary_r1.py` permits exactly one extra semicolon inside the single Configuration column. It requires the complete unique AS_Bui2008 token and float values .2f/2.55f, rejoins only those two fragments, and leaves all other strings unchanged. OFF rows retain the original header width. Unexpected widths, duplicated keys or malformed AS tokens fail.

`support/upl_c08_asplane_adopt_CPU_r1.py` is a separately reviewed offline operation for this CPU smoke only. It verifies the original zero exits, process creation/exe/argv/parent records, admission and every consumed file stat; it reruns the original input, registry, step, frame, exclusion, NoPen, AS coefficient/exponent, unique260 retirement and source-import log checks. It binds itself, the strict parser and this note before/after. It writes only the fresh `logs/upl_c08_asplane_smoke_CPU_r1.adopted_run.json`; it never changes the failed original receipt or reruns the target. Successful actual_exit/actual_Win32_exit values describe the original closed call, not a new invocation. Its own solver/decoder/build/queue counts remain zero; native and physical review remain pending.

The future `support/upl_c08_asplane_run_r2.py` mechanically clones the frozen r1 owner with only three local changes: import the strict summary, accept either `:` or `=` in the real coefficient/exponent log, and include the strict summary module stat in consumed inputs. It keeps the five original job tags, plans, physics, process ownership, memcheck and notification logic. The completed CPU job is adopted offline and must not be rerun. Each other job still requires the root's separate explicit authorization.
