# CPU ConsistentDev adapter r1

Authored only; no build, component, solver, Git or SHA execution. This task changes only `source/JSphCpu.cpp` and this note. Root owns the shared `FunSoilMaterial.h`, `StSoilCte` fields and independent XML admission.

- Include the shared material header. Only Symplectic Pre/Cor select `fsoil::ReturnPlaneStrain` when `SoilCte.MaterialReturn==1`; the existing fast nonsoftening/softening calls and their coefficient expressions remain literal inside the default branch. Verlet and dynamic plastic guards are untouched.
- Pass the existing six-component double elastic trial and float old kappa to the named-field shared adapter. The shared overload writes corrected stress/kappa only for `Elastic` or `Radial`. Predictor still restores `kplasnew=kplasticold`; corrector retains its original final kappa commit. No density, J, pressure, stress-rate, displacement or material-constant arithmetic is changed here.
- Each fluid loop adds one local unsigned `materialerror`, with OpenMP bitwise-OR reduction. A failed status ORs `1u<<unsigned(status)` and continues before that particle's native velocity/CODE/stress/kappa writes. After the loop barrier, release `movc` and throw one stage-specific exception with the status mask before any position update; corrector therefore also stops before its pore-pressure/J commit. No exception is thrown across the OpenMP loop and no NaN or elastic fallback is substituted.
- The error mask reports `Invalid` bit0, `ApexNeeded` bit3 and `NonConverged` bit4 under Root's declared enum order; success statuses do not set it. Successful particles may already have written their stage outputs when another particle fails: this is fatal stage rejection, not a transactional rollback or restart guarantee. The failed output scratch is never consumed by the later position pass.

Parameters and persistent kappa remain float; stress and required local return arithmetic remain double. This adapter does not admit spatial softening or define apex/cap history, and it makes no physical acceptance claim. Production builds/default regressions and any bounded selector checks require Root's separate authorization.
