# Release dev-kappa Taylor / endpoint cost and accuracy protocol

Author-only files `support/upl_material_cost_r1.cpp` and `support/upl_material_cost_r1_run.py`; no build/run or production change. After root full-read, one command is `D:/anaconda3/python.exe -X utf8 -B tests/support/upl_material_cost_r1_run.py --execution-authorized` from the case08 root. It requires closed r3 CPU source binding and unchanged original `outputs/upl_material_path_r1/input.csv`, prepared receipt, existing DOP853 `reference.csv` and reference checks. There is no new reference integration, old-object reuse, old actual-sft extraction, GPU test, spatial solve, half chain or public parameter.

The retained 22680-row input is read once; only its canonical candidate_general rows define 84 paths/7560 increments. Both methods independently replay those same paths from the same initial stress and zero float kappa, with the original three load/unload segments and all three fits / phi-cohesion-psi laws. Endpoint calls the actual production `fsoil::ConsRelationEPsft`. Taylor follows the already reviewed linearized_dev protocol: coefficients at old kappa, trial I in f_kappa, `lambda=f/(G+9K*alpha*beta-f_kappa/sqrt(3))`, beta frozen for the stress update, dev-kappa increment lambda/sqrt(3), and no final yield projection. It is a test approximation, not a second production selector. Both use float material/saved history and local double, and their entries validate the same material domain. This comparison has the same material law/history definition, unlike the former actual-sft versus endpoint model comparison.

Before timing, one accuracy replay writes both methods' actual states, continuous local history, saved float history, compliance plastic strains, closure, yield residual and iteration count. Strain closure uses the original `2e-12+2e-10*abs(strain)` budget; positive Taylor yield residual is an observation, not an invented failure gate. The existing reference is joined by model/N/step, reconstructing the declared diagonal stress from I and positive signed q. Saved-kappa error includes float storage along the trajectory; continuous local and saved-history errors are reported separately. `accuracy_by_path.csv` contains 168 groups and no fitted reference or new physical acceptance limit.

Two timing phases use identical loop/call/checksum overhead for both methods. Fixed-common-incoming replays the same 7560 incoming trial states prepared from the endpoint trajectory before timing; its origin is explicit and is not called theoretical truth. Independent-path timing measures the two independently advancing full paths. Both have one untimed warmup, a shared repeat count calibrated from the faster warmup toward 30ms, seven batches with alternating first method, and median ns/return. A noinline boundary and volatile function pointer prevent cached-return elimination; all returned six stress components/history contribute to an observable checksum. Counts, iterations, finite returns and repeated-result checksum must agree across a method's batches; failed returns cannot be labelled faster successful returns. Parsing, I/O, reference joins and compliance calculations are outside the clock. The timed driver still contains identical state/counter/checksum overhead, so these are entry-plus-driver measurements, not exact isolated machine cycles.

Standalone MSVC14.36 flags `/O2 /MT /fp:precise /GL-` match the authoritative CPU project MaxSpeed/static CRT/no whole-program ClCompile settings; one executable contains both methods. No engine object or Chrono/runtime DLL is linked. The component is serial CPU, without OpenMP regions; no claim is made about GPU, eight-thread solver throughput, server duration or whole-case speedup. The runner refuses a concurrently observed build/solver before timing and never stops it or retries automatically. Read `timings.csv`, `cost_summary.csv`, the actual minimum batch duration/range and accuracy groups together. Main scope is the already validated smooth/elastic paths; it does not compare old undefined q-zero/apex paths with new successful apex work.
