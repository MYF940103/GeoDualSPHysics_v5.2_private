# Recoverable, closed ILK cache cleanup (author only)

New assets are `tests/support/c08_cache_cleanup_r1.py` and this note. Root must fully review them and the final `logs/c08_cache_cleanup_r1.inventory.json` before separately invoking apply. Author does not execute cleanup, restore, compression, deletion, builds, solvers, readers, VTK, Git or notification. Existing complete/partial cleanup evidence causes refusal; this tag is one attempt with no automatic retry. No directory is deleted.

Only inventory-listed literal `.ilk` files below C08 `tests/outputs` can be considered. No new candidate search is performed. The complete inventory must bind original stat, passed closed build and actual rc0/Win320 tool receipts, no active original child and no scientific/active binding. Dependency documents and declared protected roots remain bound. Parse failures are retained: if any exist, explicit quarantined/no-ILK-reference flags and every original raw-screen result are required; nothing is silently counted as parsed. Root independently reviews this closed fallback, including conservative protected parents. Active build processes cause refusal. Current executable parents and all protected roots (including current source, runtime, PRE and HG0 dependencies) are excluded. Literal source/src/frozen/native/data/particles/figures/configs/logs/runtime path components are refused. Root formal files outside outputs cannot qualify.

Before any cache mutation, absolute containment, all parent reparse attributes, plain-file identity and stat are checked. Windows CreateFile holds each original stream with read/delete access but no write sharing; FileStandardInfo AllocationSize/EndOfFile/links and GetFileInformationByHandle FileId/volume/links are recorded. Only uncompressed, nonsparse, nonreparse files with exactly one hard link qualify; duplicate physical identities fail. This is primary unnamed stream cleanup only. Executables, pdb/obj, scientific raw BI4/NBI4, typed/native data, images/CSVs and source/program archives are never archived or deleted. The helper lowers **its own** priority to BELOW_NORMAL_PRIORITY_CLASS and never changes a solver/process priority.

The unique new `outputs/c08_cache_cleanup_r1` directory contains cache.zip (ZIP_DEFLATED level1, streaming1MiB buffers, ZIP64), inventory_consumed.json, archive_verified.json, deletions.jsonl and final check.json. Original streams are CRC32/length checked while writing, every archived stream is independently read back with CRC32/length checks, and full testzip must pass. CRC32 here is a lossless-cache recovery check, not SHA or cryptographic evidence. It is not applied to scientific data. Original handles/stats and bound inventory/closed evidence must remain unchanged. Only after successful archive_verified.json is flushed does literal unlink begin. No shell deletion, recursive deletion or computed workspace escape is used.

Each original file is rechecked for literal path, parent reparse, active/protected exclusion, FileId/volume/one-link/length/allocation/mtime immediately before Path.unlink. A durable before-unlink intent and actual observed result are written per entry. Source handles close before actual deletion/absence and final allocation observations. Failure stops later deletions, preserving partial source files, archive, manifest and journal. An interruption after an intent must be investigated from actual path/handle evidence; intent is not invented proof that deletion happened. A failed or interrupted tag is never automatically rerun.

Win32 AllocationSize is measured on original ordinary ILK streams and the new ordinary ZIP. The reported formula is actual deleted-stream allocation minus new ZIP allocation. It excludes the small JSON/journal metadata allocations and is not a precise whole-operation or volume-free increment. Volume available/free before/after is descriptive only, since active simulations and other software may write concurrently. Logical ILK byte totals are never presented as freed disk space. Hard links, NTFS compression and sparse streams are refused so the recorded stream/ZIP allocation formula is meaningful.

Separate root-authorized apply command, only after final inventory complete and full review:

`D:/anaconda3/python.exe -X utf8 -B tests/support/c08_cache_cleanup_r1.py apply --execution-authorized`

Recovery does not rebuild or rerun a simulation. Inspect archive_verified.json for the original index/path/CRC32/length/mtime. The **separate** restore mode recovers exactly one explicit original index, requires its destination still be absent, and refuses overwrite. It rechecks containment/reparse and live executable/build exclusions, streams the ZIP entry to an exclusively created original `.ilk` path, validates CRC32/length, flushes, and restores mtime/atime. Example index0 (not an automatic action):

`D:/anaconda3/python.exe -X utf8 -B tests/support/c08_cache_cleanup_r1.py restore --entry 0 --execution-authorized`

Restore leaves a unique restore_0000.json receipt, never removes partial recovery files, and never retries over them. Bytes and recorded timestamps can be restored; original FileId, ACL/security owner, alternate data streams, filesystem compression flags, original allocation extents or whole-directory metadata are **not** promised. This archival operation must not be described as a scientific-data backup or a cloud Git backup. Cache.zip and all cleanup evidence are retained.
